# 任务线「珉巧同盟」—— 第一段实现说明

对应 `任务线.docx` 第一段（到"选择是进入公司任务线"为止）。后续 questA1–A5、questF1 **本次未实现**，只保留了分支标记与钩子。

## 已实现的内容

| 设计 | 实现 |
|---|---|
| 开局询问玩家要不要玩主线 | `OnActionDef(action=On_Game_Start)` → `MCW_Event_QS1_StartStory` 窗口（两个选项：要 / 不要），只在新游戏第一个 tick 弹一次 |
| 选"要"→ 0 天直接开任务（不再等一天） | 选项里 `Effect_FireIncident(MCW_GiveQuest_QS1_MinchoMincho)`，并记 `MCW_QuestLine_Accepted` |
| 选"不要" | 只记 `MCW_QuestLine_Declined`，本局不再启动这条线 |
| 一位较强的珉巧当天加入（与玩家文化相同、固定开心果+坚韧、烹饪/社交/格斗双火） | `QuestNode_GeneratePawnWithCustomization`：`MCW_HuntedMincho_QS1`、`Tough` + `Joyous`、三个 `Major` 技能、`syncWithPlayerIdeo` |
| 一天后触发「珉巧同盟联络」（先决条件：流浪珉巧存活） | 任务内 `QuestNode_Delay 60000` + `QuestNode_AnyPawnAlive(paws=$huntedMincho)` → 触发 `MCW_Event_QS1_AllianceContact` |
| 选项"当然我们愿意加入珉巧同盟！"→ 结盟 + 空投物资 | `Effect_SetFactionRelation(MCW_Alliance_Faction, Ally)` + 6 个 `Effect_DropSupply`（薄荷冰淇淋200/砖块400/巧克力棒200/稻米300/智慧珉巧改造包1/薄荷冰淇淋联络台1） |

| 再过一天触发「回收公司联络」（无论上一步怎么选） | 任务内第二个 `QuestNode_Delay 120000`（从任务开始算的**绝对** 2 天）→ 触发 `MCW_Event_QS1_CorpContact` |
| 生成 1 名回收公司领队 + 2 名回收公司队员 | 事件的 `immediate` 里 3 次 `Effect_SpawnPawnFromFlag`（`EdgeWalkIn`，`MCW_RecycleCorp_Faction`），并用 `trackFlagName` 追踪 |
| 信件提示「回收队员到访」 | `Effect_SendLetter` |
| 回收公司的选择是强制的 | 事件上 `<forceChoose>true</forceChoose>`：不能 X 掉 / ESC 关掉，必须二选一（两个选项都无 trigger，一定有得选） |
| 选项"好吧，她是你的了"→ 与珉巧同盟决裂并永久敌对 + 奖励 | `Effect_SetFactionRelation(MCW_Alliance_Faction, Hostile, permanent=true)` + 大师级 `Apparel_PowerArmor`×2 + 极佳 `Gun_ChargeLance`×2，并把珉巧与回收小队送回地图边缘离场 |
| 选项"不可能！"→ 与回收公司永久敌对，三名成员立即进攻 | `Effect_SetFactionRelation(MCW_RecycleCorp_Faction, Hostile, permanent=true)` + `Effect_TrackedPawnsAction(Assault)` |
| 做出决定后任务才结束 | 两个选项都发 `MCW_QS1_CorpResolved`（`Effect_SendQuestSignal`），任务里 `QuestNode_Signal` 等到它才 `QuestNode_End` |
| 分支 | `MCW_QuestLine_Asked` / `MCW_QuestLine_Accepted` / `MCW_QuestLine_Declined`，以及 `MCW_QuestBranch_Mincho` / `MCW_QuestBranch_Corp` 持久 flag |

## 关于 `#nullable disable` 与框架镜像

`StellarisEventExt/` 是 **Mincho 侧对框架的扩展**，特意放在被镜像的 `StellarisEvent/` 目录之外，
因此 `Sync-StellarisEvent.ps1 -Verify` 仍然报告"32 个文件与上游一致"，重新移植框架不会碰到这些扩展。

## 给下一段（questA1 起）的接口

- 判断进入哪条线：读 Bool flag `MCW_QuestBranch_Mincho` / `MCW_QuestBranch_Corp`。
- 也可读 `MCW_QS1_AllianceJoined`（是否结盟）与 `MCW_QS1_CorpDecided`
  （后者现在只是"玩家已就回收公司做出决定"的记录，没有逻辑在读它）。
- 主线开关：`MCW_QuestLine_Asked`（开局问过）、`MCW_QuestLine_Accepted`（要走主线）、
  `MCW_QuestLine_Declined`（不走）。后续内容建议先判断 `Accepted`，避免在没开主线的存档里冒出来；
  定时器（`On_Per_Day` 之类）尤其要加这个前置判断。
- 现在可用的新 Effect（XML 里直接引类名即可）：
  - `MinchoCandyWars.StellarisEvent.Effect_SetFactionRelation`（`factionDef` / `relation` / `permanent` / `canSendHostilityLetter` / `canSendMessage`）
  - `MinchoCandyWars.StellarisEvent.Effect_DropSupplyQuality`（`thingDef` / `stuff` / `quality` / `num` / `dropLocation` / `usePlayerFaction` / `factionDef`）
  - `MinchoCandyWars.StellarisEvent.Effect_SendLetter`（`label` / `text` / `letterDef`）
  - `MinchoCandyWars.StellarisEvent.Effect_TrackedPawnsAction`（`flagNames` / `action`=Assault|Despawn / `canTimeoutOrFlee` / `toFactionDef`）
  - `MinchoCandyWars.StellarisEvent.Effect_EnsureFactionExists`（`factionDef` / `hidden`）——
    保证某派系一定存在，不存在就现创建一个并与所有派系建立初始关系。新派系相关的事件建议在
    `immediate` 最前面放一个，避免在旧存档里加载时因派系缺失而静默失效。
  - `MinchoCandyWars.StellarisEvent.Effect_SendQuestSignal`（`signalName` / `questDefName`）——
    **事件 → 任务** 的单向信号。任务侧用 `QuestNode_Signal`（`inSignal` 写不带前缀的名字）等待它。
    （框架里原本只有 ProdrakeRace 的 `QuestPart_BroadcastSignal`，那是"任务 → 任务"，没有事件侧入口。）
- 组合套路：用 `Effect_SpawnPawnFromFlag` 的 `trackFlagName` 建 Thing flag 追踪 Pawn，
  再用 `Effect_TrackedPawnsAction` 对这批 Pawn 下令（进攻 / 离场），不必为新玩法写生成逻辑。
- 好感度（沁心糖好感度、终局进度）可以直接用 `Effect_SetFlag` 的 Float flag 累计。

## ⚠ 写任务时容易踩的两个坑（本段都踩过）

1. **不要在 `<root>` 的 `nodes` 下一级直接放 `QuestNode_End`。**
   任务被接受时 `Quest.SetInitiallyAccepted()` 会发送 `Quest{id}.Initiate`，
   而 `QuestGen.InitializeQuestGen` 用 `slate.SetIfNone("inSignal", quest.InitiateSignal)` 把它
   喂给**所有没有自己指定 inSignal 的根级节点**。所以根级 End 会让任务刚开始就结束，
   后面的延时事件全部作废（而且任务栏里一闪而过，很难查）。
   要结束任务就把它包在 `QuestNode_Signal` / `QuestNode_Delay` 里面。
2. **根级的多个 `QuestNode_Delay` 是并行的、计时从任务开始算起，不是叠加。**
   它们同样都被启动信号唤醒。所以"再过 1 天"要写 `120000`（绝对 2 天），不是两个 `60000`。
